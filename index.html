NexusFrame Mini-Browser

Browse embedded web applications inside a sandboxed frame. All requests originate with your site's Referer header.

Note on X-Frame-Options & CSP

Standard homepages like google.com or youtube.com block direct iframe embedding for clickjacking protection. Use embed-friendly endpoints or click Open External if a site refuses to connect.

Site blank or "Refused to connect"?

Many websites send X-Frame-Options: DENY to block embedding inside iframes.

How Browser-in-Browser Works

1. Referrer Tracking: Every page loaded inside this <iframe> receives your main website's domain in its HTTP Referer header (controlled via referrerpolicy="origin").

2. Why Google & YouTube Homepages Block Iframes: Major platforms set X-Frame-Options: SAMEORIGIN or Content-Security-Policy: frame-ancestors headers to prevent clickjacking attacks. That is why we use official embeddable URLs (like youtube.com/embed/... and Google Maps Embed) for the presets.

3. Want to load any site without blocks? Pure frontend HTML/JS cannot bypass browser security headers. To run any website seamlessly inside your frame, you must pair this UI with a Backend Reverse Proxy (e.g., Node.js/Ultraviolet) that strips X-Frame-Options headers before serving the page.
